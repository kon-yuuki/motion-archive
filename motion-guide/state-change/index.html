StateChange

UIのアニメーションは、表示される瞬間だけではありません。押した後、処理中、完了、失敗まで含めると、操作中に迷いにくくなります。

Compare

状態が変わると、安心して操作できる。

ボタンは見た目がきれいでも、押した後が変わらないと不安になります。 hover、pressed、loading、complete を分けると、今どうなっているかが伝わります。

押す前は、通常の見た目で待機します。

通常状態。まだ何も起きていないことが分かる、落ち着いた見た目です。

Flow

1つの操作を、状態の流れで考える。

「ボタンを押したら動く」だけでは、処理中や完了後の見え方が抜けやすくなります。 どの状態が何秒で切り替わるかを決めると、実装者も作りやすくなります。

  1. 01 Idle

    押せる状態。ラベルが読めて、他の要素より目立ちすぎない。

  2. 02 Pressed

    押した瞬間に 0.1 秒程度で少し沈む。操作が届いたことを返す。

  3. 03 Loading

    処理中はラベルかインジケーターを出す。連打できないことも見た目で伝える。

  4. 04 Complete

    完了したら色や文言を変える。必要なら短い時間だけ表示して戻す。

Language

「押した後」を指示に入れる。

アニメーション指示では、最初の表示だけでなく、ユーザーが操作した後の状態も決めておくと迷いにくくなります。

伝わりにくい言い方

送信ボタンに押した感を付けてください。処理中もいい感じにしてください。

伝わりやすい言い方

押した瞬間に 0.1 秒で 2px 沈む。処理中はラベルを「送信中」に変え、スピナーを出す。完了後は「送信済み」を 1.2 秒表示して戻す。

Request sample

そのまま使える指示文

状態名を揃えると、デザインレビューでも実装レビューでも同じ話をしやすくなります。

送信ボタンは idle / pressed / loading / complete の4状態を持つ。pressed は 0.1 秒で 2px 下がる。loading ではラベルを「送信中」にし、ボタン幅は変えない。complete は「送信済み」を 1.2 秒表示してから idle に戻る。
