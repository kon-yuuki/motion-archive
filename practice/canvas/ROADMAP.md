# X Scroll Visual Gallery 自作ロードマップ

## このロードマップのゴール

`/visual-gallery/` の中核である、横方向に無限移動できるThree.js画像ギャラリーを自力で実装する。

最初から完成形を写さず、各ステップで一つの仕組みだけを追加する。前半ではThree.jsの基本と画像表示を固め、中盤で操作と無限ループを作る。シェーダーによる視差とたわみは、ギャラリーが正しく動いた後に加える。

練習中に編集するファイルは次の3つ。

- `index.html`：canvasと、必要になったDOM要素を書く
- `style.scss`：canvasとページの見た目を整える
- `script.js`：Three.js、入力処理、アニメーション、シェーダーを書く

初回はステップ0〜6を順番に進める。ステップ7以降は、必要なときに参照する。

## 学習の進め方

1. 一度に進めるのは一つのステップだけにする。
2. コードを書く前に、そのステップの「目的」を自分の言葉で説明する。
3. 完了条件をブラウザで確認してから次へ進む。
4. 動かないときは、Consoleのエラーと現在のコードを確認する。
5. `/visual-gallery/` の完成コードは答え合わせまで読まない。

各ステップを終えたら、このファイルのチェックボックスを `[x]` にする。

## Phase 1：1枚のPlaneを正しく描く

### Step 0 — 練習ページの土台を確認する

- [x] HTMLにcanvasが一つだけある
- [x] canvasが画面全体を覆っている
- [x] JavaScriptからcanvasを取得できる
- [x] Consoleにエラーがない

目的：HTML、CSS、JavaScriptの接続を先に安定させる。ここに問題があると、Three.js側の原因と区別できなくなる。

完了条件：`/practice/canvas/`を開くと、余白やスクロールバーのないcanvasが表示される。

### Step 1 — renderer、Scene、Cameraの役割を分ける

- [x] `WebGLRenderer`を作り、既存のcanvasを渡す
- [x] `Scene`を作る
- [x] `PerspectiveCamera`を作る
- [x] CameraをPlaneが見える位置へ移動する
- [x] `renderer.render(scene, camera)`で一度描画する

目的：Three.jsの最小構成を理解する。Sceneへの追加とcanvasへの描画は別の処理であることを確認する。

完了条件：単色のPlaneが画面に表示される。

### Step 2 — CSSサイズと描画解像度を一致させる

- [x] ビューポートの幅と高さをCSSピクセルで取得する
- [x] `renderer.setSize()`でdrawing bufferのサイズを合わせる
- [x] Cameraのaspectをビューポートの縦横比に合わせる
- [x] `devicePixelRatio`をrendererへ渡す
- [x] DPRは最大2程度に制限する

目的：canvasをCSSで引き伸ばしたときのぼやけと、Cameraのaspect不一致による歪みを防ぐ。

完了条件：Planeの輪郭が鮮明で、ブラウザの縦横比を変えても形が不自然に伸びない。

### Step 3 — リサイズ後もCameraとPlaneを正しく保つ

- [x] `resize`イベントで最新の幅と高さを取得する
- [x] rendererのサイズを更新する
- [x] Cameraのaspectを更新する
- [x] `camera.updateProjectionMatrix()`を呼ぶ
- [x] リサイズ後に再描画する

目的：Cameraの設定値を変えただけでは投影行列へ反映されないことを理解する。

完了条件：ブラウザを何度リサイズしてもPlaneが消えたり歪んだりしない。

### Step 4 — 画像をTextureとして1枚のPlaneへ貼る

- [x] 練習用画像を1枚選ぶ
- [x] `TextureLoader`で読み込む
- [x] Materialの`map`へTextureを渡す
- [x] Textureの読み込み完了後に描画する
- [x] `texture.colorSpace`を設定し、画像の色を確認する

目的：画像ファイルが、Texture、Material、Meshを通って画面へ出る流れを理解する。

完了条件：単色ではなく、選んだ画像がPlaneに表示される。

### Step 5 — Planeの縦横比を決める

- [x] Planeを`1 × 1`で作り、`scale`で表示サイズを変える
- [x] 補正したPerspectiveCameraで`1ワールド単位 = 1 CSS px`にする
- [x] 画像のaspectからPlaneの高さを決める
- [x] 狭い画面ではPlane幅をビューポート内へ収める

目的：Geometryを作り直さず、CSS pxを基準にしたレイアウト値を`scale`で管理できるようにする。

完了条件：デスクトップと狭い画面の両方で、Planeが画面から極端にはみ出さない。

### Step 6 — `object-fit: cover`と同じ切り抜きを作る

- [ ] 画像とPlaneのaspectを比較する
- [ ] 横長画像ではTextureの横方向を切り抜く
- [ ] 縦長画像ではTextureの縦方向を切り抜く
- [ ] `repeat`と`offset`で中央を基準に切り抜く
- [ ] 画像を引き伸ばさずPlane全体を埋める

目的：Planeの形と画像の形が違っても、画像を変形させずに表示する。これはCSSの`object-fit: cover`に相当する。

完了条件：人物や円など、比率の分かる被写体が縦横に伸びていない。

## Phase 2：複数のPlaneを横一列に並べる

### Step 7 — 複数画像を同じ仕組みで生成する

- [ ] 画像URLの配列を用意する
- [ ] 配列を反復してTexture、Material、Meshを作る
- [ ] 作ったPlaneを配列へ保存する
- [ ] PlaneごとのTextureも後から参照できるように保存する
- [ ] Geometryを全Planeで共有する

目的：1枚専用の変数を、任意の枚数を扱えるデータ構造へ変える。共有できるGeometryを再利用し、無駄な生成も避ける。

完了条件：すべての画像が同じ大きさのPlaneとして表示される。

### Step 8 — Planeの幅と余白から横位置を計算する

- [ ] Plane幅に対する割合でgapを決める
- [ ] `stepX = planeWidth + gap`を作る
- [ ] 配列indexから各PlaneのX座標を計算する
- [ ] 列全体が画面中央を基準に並ぶよう開始位置を求める

目的：Planeごとに座標を手書きせず、枚数や幅が変わっても成立するレイアウト式を作る。

完了条件：画像が重ならず、等間隔で横一列に並ぶ。

### Step 9 — 描画ループを一つにまとめる

- [ ] 更新と描画を行う関数を作る
- [ ] `requestAnimationFrame()`で次のフレームを予約する
- [ ] 1フレーム内の順番を「状態更新 → Plane更新 → render」にする
- [ ] 同じループを重複して開始しない

目的：入力イベントから直接あちこちを描画せず、画面更新の入口を一つにする。

完了条件：ループ中もConsoleエラーがなく、同じ見た目を安定して描画できる。

## Phase 3：ドラッグとホイールで横移動する

### Step 10 — 一つのoffsetで列全体を移動する

- [ ] ギャラリー全体の移動量を表す`offset`を作る
- [ ] 各Planeの基準位置にoffsetを加える
- [ ] 仮の数値をoffsetへ入れて、列全体が動くことを確認する

目的：各Planeを個別操作せず、ギャラリー全体の状態を一つの値で管理する。

完了条件：offsetを変えるだけで全Planeが同じ距離だけ横移動する。

### Step 11 — Pointer Eventsでドラッグ量を取得する

- [ ] `pointerdown`で開始X座標と開始offsetを保存する
- [ ] `pointermove`で現在位置との差を求める
- [ ] pxの移動量をThree.jsのワールド単位へ変換する
- [ ] `pointerup`と`pointercancel`でドラッグを終了する
- [ ] Pointer Captureでcanvas外へ出ても操作を継続する

目的：マウスとタッチをPointer Eventsへ統一し、ドラッグ開始時の状態を基準に移動量を求める。

完了条件：速くドラッグしてcanvas外で指やボタンを離しても、操作中の状態が残らない。

### Step 12 — ホイール入力を横移動へ変換する

- [ ] `wheel`イベントの`deltaX`と`deltaY`を読む
- [ ] 絶対値の大きい方向を主要な入力として使う
- [ ] `deltaMode`をpxへ換算する
- [ ] ホイール量をワールド単位へ変換する
- [ ] 必要な範囲だけ既定のスクロールを止める

目的：マウスホイール、トラックパッド、横スクロールを同じ横移動へまとめる。

完了条件：縦ホイールと横スワイプのどちらでもギャラリーが横へ動く。

### Step 13 — targetとcurrentを分けて慣性を作る

- [ ] 入力が変更する`targetOffset`を作る
- [ ] 実際の表示位置を表す`currentOffset`を作る
- [ ] 毎フレーム、差分の一定割合だけcurrentをtargetへ近づける
- [ ] 差が十分小さくなったら値を揃える

目的：入力値をそのまま表示位置にせず、遅れて追いつく状態を作る。これが操作後の余韻になる。

完了条件：ドラッグを止めた後も少しだけ動き、振動せず停止する。

## Phase 4：横移動を無限ループにする

### Step 14 — 一周分の幅を求める

- [ ] `loopWidth = stepX × Plane枚数`を計算する
- [ ] 各Planeが一周する範囲を図に描いて確認する
- [ ] リサイズ時にloopWidthを再計算する

目的：無限ループに必要な折り返し範囲を、レイアウトと同じ値から求める。

完了条件：Plane枚数や幅を変えても、一周分の値を手修正せず計算できる。

### Step 15 — 座標を中央基準で折り返す

- [ ] 負数でも安定する剰余計算を作る
- [ ] 座標を`-loopWidth / 2`から`loopWidth / 2`へ収める
- [ ] Planeごとの最終X座標だけを折り返す
- [ ] 入力値を急に0へ戻さない

目的：連続した入力を保ったまま、画面外へ出たPlaneだけを反対側へ再配置する。

完了条件：左右どちらへ長時間動かしても、空白や大きなジャンプが見えない。

### Step 16 — ループ境界をまたぐ最短距離を求める

- [ ] targetとcurrentの単純な差で起きる逆走を確認する
- [ ] ループを考慮した最短の差分を計算する
- [ ] 慣性計算へ最短差分を使う

目的：折り返し境界の両側にある値を、遠く離れた値として扱わないようにする。

完了条件：境界付近でもPlaneが一周分逆走しない。

## Phase 5：ShaderMaterialへ移行する

### Step 17 — 見た目を変えずShaderMaterialへ置き換える

- [ ] 最小のVertex Shaderを書く
- [ ] `projectionMatrix`と`modelViewMatrix`で座標変換する
- [ ] UVをvaryingでFragment Shaderへ渡す
- [ ] Fragment ShaderでTextureを表示する
- [ ] Textureをuniformとして渡す

目的：シェーダー導入前後で見た目を変えず、問題がMaterialにあるのか移動処理にあるのかを切り分ける。

完了条件：`MeshBasicMaterial`を使っていたときと同じ画像が表示される。

### Step 18 — Shader内でcover表示を再現する

- [ ] `uTextureRepeat`と`uTextureOffset`をuniformにする
- [ ] JavaScriptで求めたcover値をuniformへ渡す
- [ ] Fragment ShaderでサンプリングUVを組み立てる
- [ ] 画像ごとの注目位置をoffsetへ反映する

目的：Textureの切り抜きをシェーダー側で制御し、後の視差表現へつなげる。

完了条件：縦横比の違う画像でも、意図した被写体を残してPlane全体を埋められる。

### Step 19 — Planeの位置からUV視差を作る

- [ ] Plane位置を画面幅に対する`-1〜1`へ正規化する
- [ ] 正規化位置からTexture offsetを少しずらす
- [ ] 画像端が見えないよう、先にTextureへ余白を持たせる
- [ ] 移動方向と画像の動く方向を確認する

目的：Planeの移動量とTexture内部の移動量に差をつけ、奥行きを感じる視差を作る。

完了条件：Planeを動かすと、画像が表示窓の中で少し遅れて動く。画像端は見えない。

### Step 20 — 移動速度からPlaneの外形をたわませる

- [ ] 前フレームとの差から移動方向と速度を求める
- [ ] 最大変形量を制限する
- [ ] 変形量を`uWarpVector`としてVertex Shaderへ渡す
- [ ] Plane中央ほど大きく、端ほど小さく頂点を移動する
- [ ] サンプリング用UVは変形前の座標から作る
- [ ] Planeの分割数を増やして滑らかさを比較する

目的：画像そのものを引き伸ばさず、画像を見せるマスクの外形だけを移動方向へたわませる。

完了条件：速く動かしたときだけPlaneがたわみ、停止すると元の長方形へ滑らかに戻る。

## Phase 6：完成形として破綻をなくす

### Step 21 — 押している間だけ奥へ沈める

- [ ] depthにもtargetとcurrentを用意する
- [ ] `pointerdown`で目標Z座標を奥へ移す
- [ ] `pointerup`で目標を0へ戻す
- [ ] offsetとは別の補間率で追従させる

目的：ドラッグ開始と終了を、カーソルの形だけでなく奥行きの変化でも伝える。

完了条件：押した瞬間に急変せず、列全体が滑らかに沈んで戻る。

### Step 22 — 必要なときだけ描画ループを回す

- [ ] 静止中は`requestAnimationFrame`を止める
- [ ] 入力開始時にループを起動する
- [ ] offset、depth、warpが収束したら停止する
- [ ] `frameId`で二重起動を防ぐ

目的：静止画面でGPUを動かし続けず、必要なときだけ描画する。

完了条件：静止後にループが止まり、次の操作で再開する。

### Step 23 — 狭い画面、画面端、入力中断へ対応する

- [ ] スマホ幅でPlaneサイズとgapを確認する
- [ ] `touch-action`を意図に合わせて指定する
- [ ] `pointercancel`でもドラッグ状態を解除する
- [ ] リサイズ中にloopWidthが0や不正値にならないよう守る
- [ ] タブを切り替えて戻ったときに操作状態が残らないか確認する

目的：通常操作だけでなく、ブラウザが入力を中断するケースでも状態を壊さない。

完了条件：マウス、トラックパッド、タッチ、狭い画面で基本操作が成立する。

### Step 24 — TextureとThree.jsリソースを片付ける

- [ ] 不要になったGeometryを`dispose()`する
- [ ] MaterialとTextureも`dispose()`する
- [ ] animation frameをキャンセルする
- [ ] 追加したイベントリスナーを解除できる構造にする

目的：ページ切り替えや再初期化を繰り返しても、GPUメモリとイベント処理を増やさない。

完了条件：初期化と破棄を繰り返してもPlaneや入力処理が重複しない。

### Step 25 — ギャラリーのUIを仕上げる

- [ ] ヘッダーやInfoボタンをcanvasより前面へ置く
- [ ] UI操作がcanvasのドラッグに奪われないようにする
- [ ] ドラッグ中だけカーソルを`grabbing`へ変える
- [ ] `prefers-reduced-motion`時の変形量や補間を弱める
- [ ] 画像の代替情報や、WebGLが使えない場合の表示を検討する

目的：動くデモとして終わらせず、操作中に迷わず、情報も読めるページにする。

完了条件：UIを押したときにギャラリーが動かず、キーボード操作でも主要情報へ到達できる。

- [ ] 入力後に適度な余韻がある

- [ ] 画像が引き伸ばされず、Plane全体を覆う

- [ ] 速度に応じてPlaneの外形がたわむ
- [ ] 押している間の状態変化が伝わる
- [ ] リサイズ、スマホ、入力中断で破綻しない

## 困ったときの切り分け順

1. Consoleにエラーがないか確認する。
2. renderer、Scene、Camera、Planeのどこまで作れているか確認する。
3. ShaderMaterialを一時的にMeshBasicMaterialへ戻す。
4. Textureを外して単色に戻す。
5. 無限ループを外して、通常の横移動だけ確認する。
6. 慣性を外して、入力値を直接offsetへ入れる。
7. 複数Planeを1枚に減らす。

複雑な完成形から原因を探すより、一つ前の動いていた状態へ戻す方が早い。

## 用語集

- drawing buffer：canvas内部で実際に描画するピクセル領域
- aspect：横幅を高さで割った縦横比
- world unit：Three.jsの3D空間で使う長さの単位
- Texture：画像をGPUで扱える形にしたデータ
- UV：Geometry上の位置とTexture上の位置を対応させる座標
- uniform：JavaScriptからシェーダーへ渡す、描画中に共通の値
- varying：Vertex ShaderからFragment Shaderへ補間して渡す値
- easing：現在値を目標値へ少しずつ近づける処理
- Pointer Capture：ポインターが要素外へ出ても、その要素で入力を受け続ける仕組み
- frustum：Cameraに映る立体的な範囲
- DPR：1 CSSピクセルに対応する物理ピクセルの比率
