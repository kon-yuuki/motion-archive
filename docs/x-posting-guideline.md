# X Posting Guideline

このドキュメントは、UI Gallery のデモをもとに X 投稿を作るための方針です。対象は UI Gallery で、Motion Archive の表現実験は含めません。

## アカウントのコンセプト

Web UI の小さな「使いやすさ」を、動くデモで検証するフロントエンドエンジニア。

見た目のデザイン批評ではなく、操作したときの迷い、読みやすさ、状態変化、気持ちよさを分解して伝えます。

## 目指すポジション

- 使いやすい UI の「ふるまい」を検証する。
- 見た目ではなく、操作したときの気持ちよさを分解する。
- UI の小さな違和感を、動くデモと実装目線で説明する。

参考にしたい方向性は、動く UI を見せる力、気持ちいい動きの言語化、Web デモとしての見せ方、使いやすさの分解、ユーザー心理から説明する力です。ただし、海外 UI 紹介や見た目だけの批評には寄せません。

## 発信対象

- UI の細かい挙動を改善したいフロントエンドエンジニア
- 実装時の制約も理解したいデザイナー
- プロダクトの操作感を良くしたい個人開発者、UI 実装者

## 発信の軸

- 小さな挙動差を比較する。
- 使いにくくなる理由を、ユーザーの行動から説明する。
- 改善案は実装時の確認ポイントまで落とす。
- 専門用語より先に、使う人がどう感じるかを書く。
- 最後に実装目線の一言を添える。

## 投稿フォーマット

### 比較デモ型

```text
〇〇の挙動を3パターンで比較しました。

❌ A
問題点

❌ B
問題点

✅ C
改善点

UIの使いやすさは、
見た目より“〇〇”で変わることが多い。
```

### あるある改善型

```text
〇〇が使いにくくなる原因。

・〇〇
・〇〇
・〇〇

改善するなら、

・〇〇
・〇〇
・〇〇

小さいUIほど、
こういう細かい配慮が体験に出る。
```

### チェックリスト型

```text
〇〇 UIを作るときに確認したいこと

・〇〇できるか
・〇〇で破綻しないか
・〇〇が伝わるか
・〇〇時も自然か
・スマホでも成立するか

“作れた”ではなく、
“使う場面で困らないか”まで見る。
```

### 実装メモ型

```text
〇〇の挙動を作るとき、
実装ではこのあたりを見る。

・表示位置
・遅延時間
・閉じる条件
・画面端の処理
・スクロール時の追従
・スマホ時の代替UI

UIの実装は、見た目より例外処理で差が出る。
```

## 文体ルール

- 日本語で書く。
- デザイナーにも伝わる言葉にする。
- いきなり専門用語から入らない。
- 断定しすぎず、でも結論ははっきり言う。
- 「これはダメ」より「こうすると使いやすくなる」と書く。
- アクセシビリティ警察っぽい言い方を避ける。
- 抽象的な UX 論だけで終わらせない。
- 実装目線の一言を添える。

## NG方針

- 単なる海外 UI 紹介にしない。
- 見た目だけのデザイン批評にしない。
- 専門用語だけで説明しない。
- 「NG」「ダメ」だけで終わらせない。
- デモが派手に動くことだけを成果にしない。
- アクセシビリティを説教調で語らない。

## 投稿サンプル

### Tooltip Behavior

```text
ツールチップの出方を3パターンで比較しました。

❌ すぐ出る
少し触れただけでも表示されて、操作の邪魔になりやすい。

❌ 毎回遅れる
連続で確認したいときに、待ち時間が積み重なる。

✅ 初回だけ少し待つ
誤表示を減らしつつ、操作中は軽く感じられる。

UIの使いやすさは、
見た目より“出るタイミング”で変わることが多い。
```

### Button Loading State

```text
送信ボタンを作るときに確認したいこと

・押した直後に反応が伝わるか
・二重送信を防げるか
・待っている状態が読めるか
・失敗したとき戻れるか
・スマホでも押し間違えにくいか

“送信できる”だけでなく、
“押した後に不安にならないか”まで見る。
```

### Form Error Behavior

```text
フォームエラーが使いにくくなる原因。

・どこが間違いか見つけにくい
・入力中に何度も強く怒られる
・直したあともエラーが残って見える

改善するなら、

・該当箇所の近くに出す
・入力中は邪魔しすぎない
・直ったら状態をすぐ更新する

小さいフィードバックほど、
不安を増やさない出し方が大事。
```

## 成果指標

- 投稿だけで「何が問題で、どう改善したか」が伝わる。
- デモ動画を見た人が、自分の UI で確認すべき点を言える。
- デザイナーとエンジニアの両方が会話に使える。
- いいね数だけでなく、保存、引用、実装相談、デモへの流入を見る。
- 投稿後に次のデモテーマや改善観点が増える。

## 今後作ると良さそうなデモ

- Hover Intent: 誤 hover と本当に見たい hover を分ける。
- Toast Timing: 読める時間、消える条件、連続表示を比較する。
- Form Error Behavior: 入力中、送信後、修正後のエラー表示を比較する。
- Button Loading State: 押した後の待ち時間と二重送信防止を見せる。
- Bottom Sheet Behavior: 開閉、ドラッグ、画面高さの違いを比較する。
