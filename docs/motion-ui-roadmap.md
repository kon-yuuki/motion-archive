# Motion & UI Roadmap

## 目的

**Motion & UIを、自分の専門性を蓄積しながら将来の仕事につながる「個人のポータル」に育てる。**

短期的には、現在あるコンテンツを整理し、問い合わせを受けられる状態までサイト全体を設計・実装して公開する。

公開後は、会社員を続けながら**自分の力で月10万円を稼ぐ経験を作ること**を目指す。最終的には、自分で仕事や収入を作り、働く時間や場所をコントロールできる状態につなげる。

---

## 今の状況

Motion Archive、UI Gallery、Motion Guideを中心に、すでに公開できる候補コンテンツはある。一方で、制作途中に増えたページも含まれており、サイト全体で次の点が整理できていない。

- 公開時に使うページと、現時点では使わないページ
- 各コンテンツの役割と、サイト全体での優先順位
- トップ、一覧、詳細ページをつなぐ導線
- ページごとに異なるナビゲーション
- 問い合わせへつなげる場所と見せ方

そのため、デザインを始める前にコンテンツと動線を整理する。ここでサイトの骨格を決めてから、デザイン、実装、公開へ進む。

---

## 公開までの進め方

公開までを5つのフェーズに分ける。各フェーズの完了条件を満たしてから次へ進み、デザイン中や実装中にサイト構成が揺れ続ける状態を避ける。

# Phase 1：既存コンテンツとページを整理する

リポジトリ内のページをすべて棚卸しし、公開するページと、それ以外を分ける。残す基準は、Motion & UIの目的に必要かどうかとする。

## やること

- [ ] 現在存在するページを一覧にする
- [ ] 各ページの目的、内容、完成度、入口、遷移先を確認する
- [ ] ページを「公開する」「統合する」「公開後に検討する」「非公開にする」に分類する
- [ ] Motion Archive、UI Gallery、Motion Guideの役割を言葉にする
- [ ] Categories、Easings、Visual Gallery、Practiceなどの扱いを決める
- [ ] WIPやpendingの作品を、公開対象に含めるか決める
- [ ] 重複している内容や、役割の曖昧なページを整理する
- [ ] 公開時に必要だが、まだ存在しないページを洗い出す

## 成果物

- ページ棚卸し表
- 公開対象ページの一覧
- 統合、保留、非公開にするページの一覧と理由
- 各コンテンツ群の短い役割説明

## 完了条件

**公開時に何を見せ、何を見せないかが決まっていること。**

---

# Phase 2：サイト構成と動線を決める

Phase 1で残したコンテンツをもとに、サイトマップと回遊方法を設計する。初めて訪れた人がサイトの目的を理解でき、興味のあるデモを見たあとに、作者や相談窓口へ迷わず進める状態を目指す。

## やること

- [ ] 公開版のサイトマップを作る
- [ ] グローバルナビゲーションの項目を決める
- [ ] トップページの役割と掲載内容を決める
- [ ] 一覧から詳細、詳細から次のコンテンツへ進む導線を決める
- [ ] Motion Archive、UI Gallery、Motion Guideを横断する導線を決める
- [ ] Aboutの必要性と内容を決める
- [ ] 問い合わせへの入口を置くページと位置を決める
- [ ] スマホでのナビゲーション方法を決める
- [ ] 主要な閲覧経路をワイヤーフローにする

## 想定する主要動線

1. トップでMotion & UIの目的を知る
2. Motion Archive、UI Gallery、Motion Guideから興味のある入口を選ぶ
3. 一覧から個別のデモや解説を見る
4. 関連コンテンツや一覧へ戻って回遊する
5. 作者について知る、または相談する

## 成果物

- 公開版サイトマップ
- グローバルナビゲーション案
- 主要ページの掲載要素一覧
- PC、スマホのワイヤーフロー

## 完了条件

**主要ページの役割と、ページ間をどう移動するかが決まっていること。**

---

# Phase 3：問い合わせを含めてデザインする

確定したサイト構成をもとに、公開版のデザインを作る。作品を目立たせるだけでなく、Motion & UIが何のサイトなのか、自分が何を得意としているのか、どんな相談ができるのかが自然に伝わる形にする。

## やること

- [ ] サイト全体のデザイン方針を決める
- [ ] タイポグラフィ、色、余白、カード、ボタンなどの基本ルールを決める
- [ ] トップページをデザインする
- [ ] 各一覧ページをデザインする
- [ ] 作品詳細と解説ページの共通部分をデザインする
- [ ] Aboutまたはプロフィール部分をデザインする
- [ ] 問い合わせへの導線をデザインする
- [ ] 問い合わせフォームを設計する
- [ ] ヘッダー、スマホメニュー、フッターをデザインする
- [ ] PCとスマホの主要画面を確認する

## 問い合わせフォームの候補項目

- 名前またはニックネーム
- メールアドレス
- 相談ジャンル
  - モーション実装
  - フロントエンド実装
  - Webサイト制作
  - WordPress改修
  - その他
- 対象サイトURL（任意）
- 相談内容
- 希望時期
- 予算感（任意）

この段階では営業色を強くしすぎない。「モーション実装やWeb制作について、相談したいことがあればこちらからどうぞ」程度の温度感にする。細かい料金表は作らず、どんな相談が来るかを見ること自体を市場検証にする。

## 成果物

- デザイン方針
- 主要ページのPC、スマホデザイン
- 共通コンポーネントのデザイン
- 問い合わせ導線とフォームのデザイン

## 完了条件

**実装時に大きな判断を残さず、主要画面と状態変化を確認できること。**

---

# Phase 4：デザインを実装へ反映する

デザインを既存のVite + Vanilla JS + SCSS構成へ反映する。既存デモの表現は活かしながら、サイト共通部分とページ間のつながりを整える。

## やること

- [ ] 共通ヘッダー、ナビゲーション、フッターを実装する
- [ ] トップページを実装する
- [ ] 各一覧ページへデザインを反映する
- [ ] 詳細ページの共通シェルを整える
- [ ] Aboutまたはプロフィール部分を実装する
- [ ] 問い合わせフォームを実装し、送信先を設定する
- [ ] 公開対象外のページをナビゲーションとビルド対象から外す
- [ ] ページタイトル、description、OG画像などの基本情報を整える
- [ ] 404ページなど、公開に必要な補助ページを確認する
- [ ] PC、スマホ、狭い画面、キーボード操作を確認する

## 実装時の方針

- 既存のデモ固有コードは、必要がない限り変更しない
- 共通化は、サイト全体で繰り返し使う部分に絞る
- 公開対象外にしたページは削除を急がず、まず入口とビルド対象を整理する
- 問い合わせフォームは送信成功、入力エラー、送信中、失敗の状態が伝わるようにする

## 確認

```sh
npm run build
```

変更したJavaScriptには、対象ファイルごとに`node --check`を実行する。

## 完了条件

**公開対象の全ページが実装され、主要な導線と問い合わせ送信が実際に動くこと。**

---

# Phase 5：公開前確認を行い、v1を公開する

公開前に、見た目だけでなく、コンテンツ、動線、フォーム、基本情報を通して確認する。問題を修正したあと、Motion & UI v1として公開する。

## やること

- [ ] 公開対象ページに抜けや仮テキストがないか確認する
- [ ] ヘッダー、フッター、一覧、詳細のリンクを確認する
- [ ] 外部リンクと参考リンクを確認する
- [ ] 問い合わせフォームを実送信して確認する
- [ ] 主要ページをPCとスマホで確認する
- [ ] 画面端、狭い画面、長い文章でも破綻しないか確認する
- [ ] WIP表示と公開範囲が意図どおりか確認する
- [ ] OGP、favicon、title、descriptionを確認する
- [ ] 本番ビルドを確認する
- [ ] Vercelへデプロイする
- [ ] 本番URLで主要動線とフォームを再確認する
- [ ] v1公開を告知する

## 完了条件

**初めて訪れた人がサイトの目的を理解し、コンテンツを回遊し、必要なら相談できる状態で本番公開されていること。**

---

## 公開後の育て方

v1公開を、反応を得るためのスタートとする。公開後は、閲覧や相談から得た反応を次の改善に使う。

# Phase 6：反応を見て改善する

- どのコンテンツが見られているか確認する
- どこから問い合わせへ進んでいるか確認する
- 実際に来た相談内容を記録する
- 分かりにくい導線や離脱しやすい箇所を改善する
- 問い合わせ項目や案内文を必要に応じて調整する

# Phase 7：Motion Archiveを100件まで積み上げる

v1公開後もMotion Archiveを継続して増やす。

## 目安

### 23件〜

v1を公開し、相談フォームを静かに設置する。

### 50件〜

コンテンツ量に合わせて、カテゴリ、タグ、検索、関連モーションなどの回遊機能を見直す。必要になる前に機能を増やさない。

### 100件〜

Motion & UIが一つのまとまった成果物になった段階で、「Motion Archiveを100件作りました」という形の発信を検討する。

# Phase 8：専門性を知識として残す

自分自身の見方が伝わるモーション事例集へ育てる。価値を出しやすい事例から取り組む。

- なぜこのモーションが気持ちいいのか
- UIとして何が使いやすいのか
- 実装するとしたらどう作るか
- CSS、JavaScript、GSAPなどの実装視点
- パフォーマンス面での注意点

Motion Archiveを、少しずつMotion & UIの知識ベースへ進化させる。

# Phase 9：月10万円につなげる

相談内容や自分の得意領域を観察し、需要が見えたものをサービスとして整える。

候補は、モーション実装、LP実装、Webサイトのフロントエンド実装、WordPress改修、既存サイトのUI改善、アニメーション追加、制作会社向けの実装支援など。最初から商品を決め切らず、実際に来た相談をもとに判断する。

最初の目標は、**副業で月10万円を継続的に得られる状態を作ること。**

---

## 今はやらないこと

方向性を広げすぎないため、次のことは一旦やらない。

- クラウドソーシング
- 会社の制作実績を無理にポートフォリオへ載せる
- 会社員として使っているXで大々的に副業募集する
- 目的のない技術学習
- 新しいサービスを次々に作る
- 完璧なポートフォリオを目指して公開を遅らせる
- 100件になるまで公開を待つ
- 整理前のページをすべてデザインし直す

---

## 迷ったときの判断基準

まず、次の問いで判断する。

> **これは、Motion & UIという自分の資産を育てる行動か？**

公開までは、もう一つ確認する。

> **これは、v1公開に必要な作業か？**

どちらにも当てはまらない作業は、一旦バックログへ移す。**技術 × 発信 × 資産 × 商売**を少しずつつなげる。

---

## 直近のゴール

現在の最優先は、**Phase 1の既存コンテンツ整理を終えること。**

その後は、次の順番でMotion & UI v1の公開まで進める。

1. 既存コンテンツとページの整理
2. サイト構成と動線の確定
3. 問い合わせを含むデザイン作成
4. デザインの実装反映
5. 公開前確認とv1公開

長期的には、**すでに育っている仕事があるから会社を辞められる状態**を目指す。Motion & UIは、そのための最初の一本目の資産として育てていく。
