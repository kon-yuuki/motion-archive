# UI Demo Guideline

このドキュメントは、UI Gallery に UI 挙動デモを追加するときの制作方針です。対象は `ui-gallery/` です。

## デモを作る目的

UI の小さな挙動差が、使いやすさにどう影響するかを動くデモで検証します。

デモでは、見た目の完成度だけでなく、操作したときに迷わないか、邪魔にならないか、読めるか、状態変化が伝わるか、狭い画面でも破綻しないかを説明します。

## デモにする価値があるテーマ

- 操作タイミングで体験が変わるもの
- 表示位置や画面端で破綻しやすいもの
- 待ち時間や読み取り時間が関係するもの
- 押した後、開いた後、閉じた後の状態が重要なもの
- スマホ、キーボード操作、狭い画面で別の配慮が必要なもの
- デザイナーとエンジニアの認識がずれやすいもの

例:

- Tooltip Behavior
- Hover Intent
- Edge Collision
- Toast Timing
- Modal Open / Close Behavior
- Button Loading State
- Form Error Behavior
- Dropdown Menu Behavior
- Bottom Sheet Behavior
- Scroll-Aware Header
- Accordion Timing
- Skeleton / Loading Behavior

## デモページの標準構成

1. 検証テーマ: 何の挙動を比較するか。
2. よくある使いにくい挙動: どんな場面で困るか。
3. 改善した挙動: どう変えると使いやすくなるか。
4. 体験上の理由: ユーザーにとって何が楽になるか。
5. 実装メモ: 実装で見るべき条件や例外。
6. スマホ・狭い画面の注意点: hover 以外の操作や表示位置。
7. X投稿用テキスト: 投稿に転用できる短い説明。

## 悪い例 / 改善例の作り方

悪い例は、実際によく起きる「少し困る」挙動にします。極端に壊れた UI を作ると比較の学びが弱くなります。

改善例は、万能な正解としてではなく「この条件ではこうすると使いやすい」という形で見せます。デモ内に複数案がある場合は、どの案を推奨するかを明示してください。

比較するときの観点:

- 表示が早すぎないか、遅すぎないか
- 読む前に消えないか
- 操作を邪魔しないか
- 画面端で見切れないか
- 押した後の状態が伝わるか
- 連続操作でも重く感じないか
- スマホでも意味が伝わるか

## デザイナー向け説明の作り方

最初に専門用語を置かず、使う人の行動から説明します。

例:

- 「hover intent」ではなく「本当に見たいときだけ出す」
- 「collision detection」ではなく「画面端でも読める位置に出す」
- 「focus management」ではなく「開いた後に迷わず操作を続けられる」
- 「prefers-reduced-motion」ではなく「動きが苦手な人には控えめにする」

必要な専門用語は、本文ではなく実装メモや補足に書きます。

## 実装メモの書き方

実装メモは、コードの細部より「何を確認すべきか」を短く書きます。

含めると良い項目:

- 表示位置
- 遅延時間
- 閉じる条件
- 連続操作時の扱い
- 画面端の処理
- スクロール時の追従
- キーボード操作
- スマホ時の代替 UI
- 動きを控えたい設定への配慮

専門用語を使う場合は、体験上の意味も添えます。

## スマホ・画面端・状態変化の確認項目

- hover できない環境でも情報が伝わるか。
- タップで開いたものを自然に閉じられるか。
- 画面端や狭い幅で見切れないか。
- スクロール中に位置が不自然にずれないか。
- 押した後、送信中、完了、失敗が区別できるか。
- キーボード操作で現在位置を見失わないか。
- 文字量が増えてもボタンやカードからはみ出さないか。
- 動きがなくても状態変化が伝わるか。

## 作ってはいけないデモの例

- 派手な動きだけで、使いやすさの説明がない。
- 悪い例が極端すぎて、現実の UI 改善に使えない。
- 専門用語の説明だけで、使う人の困りごとに触れていない。
- PC の hover だけを前提にして、スマホやキーボード操作を無視している。
- 見た目の好みだけを比較している。
- 既存構成を壊す大規模リファクタリングを伴う。

## 新規デモ追加時のチェックリスト

- `ui-gallery/<component>/` にページを追加した。
- `src/data/ui-gallery.js` にメタデータを追加した。
- `vite.config.js` の `build.rollupOptions.input` に HTML を登録した。
- 悪い例と改善例の違いが操作で分かる。
- 何が使いやすくなるのかを本文で説明した。
- 実装時に見るべきポイントを書いた。
- スマホや狭い画面での注意点を書いた。
- X投稿用の短い説明文を用意した。
- `npm run build` を実行した。
- 対象の `script.js` に `node --check` を実行した。
